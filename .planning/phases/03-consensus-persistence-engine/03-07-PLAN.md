<objective>
Milestone 3.2 core: the group-commit writer thread (decisions D-01, D-02, D-03, D-04) over the SegmentIo seam from plan 03-03.

Purpose: this thread is the only place WAL bytes are written and the only place fsync is called, which keeps blocking I/O off the Tokio runtime (R-3) and satisfies openraft's rule that all write I/O is serialized. The writer is generic over an opaque payload type so it has no dependency on the consensus library; the store adapter (plan 03-11) supplies the payload and wraps openraft's IOFlushed into an Ack.

Output: src/wal/writer.rs with unit tests on StdFsIo and FakeIo. Recovery and cache (plan 03-08) run in parallel with this plan; they share only the types in segment.rs.

  <action>
Create src/wal/writer.rs with the interfaces block. WalHandle::spawn builds the ring with RingBuffer::<WalOp<P>, WAL_RING_CAPACITY>::channel(), keeps the Producer in the handle, and moves the Consumer, the Box<dyn SegmentIo>, the config, the WalStart and the observer into a std::thread named "lightcycle-wal-writer". If WalStart.active_seq is 0 the first segment is created lazily when the first op arrives: seq 1 via create_segment(1, cfg.segment_size) then sync_dir, with a Preamble (segment_seq 1, first_index = the triggering entry's index or 0 for a non-entry op, empty state) written at offset 0 as the first record; otherwise the writer resumes at start.active_seq and start.tail_offset with start.state as the current preamble state.

The loop: consume_batch up to 512 ops into a pending Vec; encode each op into one reusable Vec<u8> buffer using record::encode_record (Entry payload is the 8-byte little-endian index followed by WalPayload::encode_into; Vote, Committed carry their blob; TruncateAfter carries flag byte then optional u64; Purge carries upto u64 then blob), stopping at cfg.max_batch_bytes and carrying the remaining pending ops to the next iteration; write_at the buffer at the tail offset; call observer.on_entries_written with one EntryLocation per Entry record (index, seq, record start offset, total record length); call sync_segment once; call observer.on_flushed with the highest entry index in the batch; then complete every ack in order with Ok. Idle behavior with no timer window: spin_loop for about 100 iterations, then set a shared parked flag, issue fence(SeqCst), re-check the ring, and thread::park_timeout(100 ms) only as a lost-wakeup backstop; try_submit publishes, issues fence(SeqCst) and unparks the writer thread if the parked flag is set. WalStats counts batches, records, bytes, syncs and records each fsync duration in a log2-microsecond histogram from day one (macOS File::sync_data is a full-device flush, about 4 ms p50, so latency numbers from this machine are correctness-only).

shutdown(self) sets a stop flag, unparks, and joins after the writer has drained the ring and acked everything. Leave segment rolling, purge, failure handling and the non-Always fsync modes to Tasks 2 and 3 but structure the loop so they slot in (a single function that writes a record run, and a single place that completes acks).

Test tracer_one_record_acked_after_sync (tempfile dir, StdFsIo, fresh WalStart, Vec<u8> payload): submit Entry index 1 payload "hello" with an ack that sends on a std::sync::mpsc channel; recv within 5 s yields Ok; shutdown; read segment 0000000000000001.wal from disk with decode_record: first record is a Preamble, second an Entry whose payload is index 1 LE followed by "hello", and stats.syncs is at least 1.

Durability ordering of the lazily created first segment (the tracer carries this so it is proven from the first commit): the writer must call create_segment, then sync_dir, and only then write the preamble and the batch, so the directory entry is durable before the first sync_segment and therefore before any ack. Property under test: if the writer omits sync_dir after create_segment, FakeIo drops the never-dir-synced segment on power_loss and this test fails.

Implement the behavior above in writer.rs. Track per-segment (first_index, last_index) in a BTreeMap seeded from WalStart.segments and updated on every entry write; on TruncateAfter cap the affected last_index values at keep_through and call observer.on_truncate; track next_index (last written entry index plus one) so a roll triggered by a non-entry op still gets a sensible preamble first_index. Purge deletion uses io.delete_segment per eligible segment followed by one sync_dir, and calls observer.on_purge(upto) after the markers are durable. The preamble state the writer re-emits at each roll is its live PreambleState (updated by Vote, Committed and Purge ops), so after any roll the newest segment alone suffices to recover vote, purged id and committed id.

Mandatory call order (under Fsync::Always; the UNSAFE modes in Task 3 make no durability promise and are exempt): roll = sync_segment(old) then create_segment(new) then sync_dir then write the new preamble then the batch then sync_segment(new) then acks; purge = write the marker record as part of the batch, sync_segment on the active segment returns Ok, and only then delete_segment for each eligible segment, then one sync_dir after the last deletion; an error from create_segment, sync_dir, delete_segment, write or sync is a fail-stop (Task 3). Never reorder these to save a sync: the directory entry of a new segment must be durable before the sync that covers its first entry, and no segment may be deleted while the only durable copy of the purge marker is still volatile.
