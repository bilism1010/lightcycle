<objective>
Milestone 3.1/3.2 glue: the openraft log storage implementation (decisions D-01, D-02, D-03, D-04) over the pieces from plans 03-07 and 03-08, plus the informational WAL bench.

Purpose: RaftLogStorage methods take &mut self and the store is moved into Raft::new, so exactly one task owns the non-Clone ring Producer, which is what makes the SPSC ring safe by construction. The store keeps the in-memory cache and bounds consistent with writer order, reports last_log_id and vote after recovery, and is the only place that depends on both openraft and the WAL.

Hardware note (user decision): NFR-1 and NFR-2 are deferred. On this macOS machine File::sync_data issues F_FULLFSYNC (about 4 ms p50 measured), so the bench is informational only and must not assert on fsync latency; the manual-only verification row in 03-VALIDATION.md stays open until the user provides a Linux NVMe host. For that reason NFR-1 and NFR-2 are deliberately NOT listed in this plan's `requirements` frontmatter: executing this plan must not mark them complete, and the bench output is never evidence for them.

  <action>
Implement WalLogStore::open_with_io: run recover on the SegmentIo, keep RecoveredLog::stats() in the store for recovery_stats(), decode the recovered vote blob (postcard Vote), purged blob (LogId) and committed blob, rebuild LogShared from RecoveredLog.locations with an empty (cold) cache sized by cfg.cache_budget_bytes, find last_log_id by reading and decoding the entry at the last location through the SegmentRead handle (None when the log is empty), then WalHandle::spawn with a SharedObserver over the shared state and the recovered WalStart. Keep vote, purged, committed and last_log_id in the store struct. get_log_state returns LogState { last_purged_log_id, last_log_id }; get_log_reader returns a WalLogReader clone; try_get_log_entries(range) serves from the cache and falls back to cache::read_entry (disk) for misses, bounded by the store's first and last index.

append(entries, callback): for each entry insert a clone into the cache (size estimate: key plus value lengths plus 32) and set last_log_id, so entries are readable the moment append returns; submit one WalOp::Entry per entry using a payload adapter whose encode_into calls postcard::to_extend on the Entry (encoding happens on the writer thread); attach the Ack only to the last op, built as a boxed closure that calls callback.io_completed(result) exactly once. Submission uses a private async helper that loops on try_submit and, when the ring is full, awaits tokio::task::yield_now() before retrying, so a Tokio worker thread is never blocked (Pitfall 2). save_vote encodes the Vote with postcard, submits WalOp::Vote with a tokio oneshot Ack and awaits it, so it returns only after the covering fsync. Every method first checks WalHandle::is_failed and returns an io::Error if true. shutdown(self) runs the writer join inside tokio::task::spawn_blocking; Drop does the same synchronously through an Option take.

Tracer test wal::store::tests::append_vote_restart (#[tokio::test], FakeIo): open, save_vote, append two Normal entries with a signalling IOFlushed and await completion, shutdown, reopen with the same FakeIo handle, and assert get_log_state reports the last log id, a LogReader returns both entries, the vote read back (via the store's accessor or get_log_state path used by openraft's read of the vote) equals the saved vote, and recovery_stats() on the reopened store reports entries_recovered 2 and torn_bytes_discarded 0.
