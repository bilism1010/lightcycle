<objective>
Milestone 3.3 transport, first half (decisions D-05, D-06, D-07, D-12): the real TCP Raft peer transport on the shared frame codec: protocol, server accept loop with Hello, lazy lane-tagged client, unary Vote and AppendEntries, and the pipelined replication lane. The chunked snapshot lane and the heartbeat-isolation proof are plan 03-17 (split out of this plan to keep each plan inside the context budget; it runs in the next wave and depends on this one).

Interpretation A4 (stated per instructions; THE USER MUST BE TOLD): D-07 literally says "one persistent connection per peer with pipelined AppendEntries", while this plan gives each peer up to THREE TCP connections: one persistent pipelined replication connection, one heartbeat connection and one snapshot connection (openraft's new_client, new_heartbeat_client and new_snapshot_client hooks). D-12 requires a separate logical channel for heartbeats and snapshots; implementing that as separate dedicated connections rather than multiplexing everything over one socket is the reading chosen, because a multiplexed socket would reintroduce head-of-line blocking, the exact failure D-12 exists to prevent. If CONTEXT.md is read as demanding strictly one TCP connection per peer, a priority-multiplexing writer is needed instead; that is a user decision and this plan does not build it. The final phase summary (plan 03-16) must repeat this so the user sees it.

Purpose: the transport is tested hermetically against a stub RaftHandler (the same trait the fake network uses) so it is proven before a Raft node exists; the real-node smoke test is plan 03-15. The listener is a separate port from Phase 5's client RPC (D-06) and has no TLS or authentication (D-08, accepted, README note in plan 03-15).

Output: src/net/{protocol,client,server}.rs and tests/transport.rs (vote, handshake, pipelined replication and negative tests). Plan 03-17 extends client.rs, server.rs and tests/transport.rs with the snapshot and heartbeat lanes.
</objective>

Create src/net/protocol.rs with the kind constants and body structs from the interfaces block; document in the module doc that kinds below 16 belong to the wire module. Create the server in src/net/server.rs: PeerServer::bind binds a TcpListener on the given address (port 0 allowed for tests) and spawns an accept loop; each accepted socket gets set_nodelay(true) and its own task that wraps the socket in Framed with a FrameCodec capped at 4096 bytes until the Hello is accepted, runs server_handshake with cfg.handshake_timeout (on any handshake failure increment handshake_failures and close), then widens the frame cap by lane (replication and heartbeat lanes: cfg.max_frame_len; snapshot lane: cfg.snapshot_chunk_size plus 64 KiB), increments accepted_by_lane, and enters the per-lane frame loop. In this task the loop handles VOTE_REQ and PREVOTE_REQ frames: decode the postcard body, call handler.vote or pre_vote, and write the response frame with the same req_id; any frame decode error, unknown kind, or FrameError closes the connection and increments decode_errors. A snapshot-lane connection is accepted, lane-counted and given its cap here, but any SNAP_* frame is an unknown kind until plan 03-17 adds the receive state machine (the connection is closed and decode_errors incremented). A single writer path (an mpsc to a writer task per connection) owns the sink so responses from concurrent handler futures never interleave.

Create src/net/client.rs with TcpNetConfig (defaults in the interfaces block), TcpNetworkFactory and PeerClient. PeerClient connects lazily on first use: TcpStream::connect under connect_timeout, set_nodelay(true), Framed with a small-cap codec, client_handshake with Hello { wire_version, cluster_id, node_id, lane }, then widen the cap per lane. For this task implement vote and pre_vote as unary calls (allocate a req_id, send, await the response frame with the matching req_id) and make every other RaftNetworkV2 method return an Unreachable error until Task 2 (append_entries, stream_append) and plan 03-17 (full_snapshot). TcpNetworkFactory::new_client, new_heartbeat_client and new_snapshot_client already return PeerClient values tagged Lane::Replication, Lane::Heartbeat and Lane::Snapshot here, so each lane lazily dials its own connection. Error mapping: connect, EOF and socket errors drop the connection and return RPCError::Unreachable so openraft backs off; timeouts return RPCError::Timeout; frame, codec and unexpected-kind errors drop the connection and return RPCError::Network; a handler error carried in the response is mapped to the remote-error variant. Add the three `pub mod` lines to src/net/mod.rs.

  <behavior>
    - pipelined_in_order: 20 AppendEntries requests streamed through PeerClient::stream_append against a stub that answers each after 20 ms; the client's output stream yields the 20 responses in request order and ServerStats.max_inflight_observed is at least 2 (requests were received while earlier ones were unanswered)
    - inflight_window_bounded: with inflight_requests = 4 and a stub that withholds responses, the server sees exactly 4 AppendEntries frames and no more until a response is released, after which the rest flow
    - response req_id mismatch, wrong kind or EOF ends the output stream with an error item and drops the connection (no resync)

    - append_entries (unary) works over the replication lane
  </behavior>
  <action>
Client: PeerClient::stream_append takes the connection out of the client for the session (leaving None so a later call reconnects), splits the Framed into sink and stream halves, spawns a writer task that pulls requests from `input`, acquires permits from two tokio Semaphores (one permit per request up to inflight_requests, and body-size-in-KiB permits capped at inflight_bytes) and sends APPEND_REQ frames with increasing req_ids without waiting for responses, and pushes each req_id into a shared queue; the returned stream reads APPEND_RESP frames, checks each req_id against the queue front (in order, single TCP connection), releases the permits, and yields Ok(AppendResult); on any mismatch, decode failure or EOF it yields one Err(RPCError::Network) item and ends. The writer task is aborted when the returned stream is dropped (wrap it in a guard type). append_entries is a unary APPEND_REQ round trip. Server: on a replication or heartbeat lane connection, APPEND_REQ frames are decoded and pushed into a bounded mpsc that backs the BoxStream passed to handler.stream_append; a per-connection task pairs each yielded AppendResult with the queued req_id and sends APPEND_RESP in order; update append_req_frames, append_resp_frames and max_inflight_observed (requests received minus responses sent); unary VOTE_REQ frames on the same connection are still served concurrently. Tests as listed, in tests/transport.rs, with the stub gaining a configurable per-request delay, a withhold gate (tokio::sync::Notify or Semaphore) and an echo of the request's identifying field so order can be asserted.
