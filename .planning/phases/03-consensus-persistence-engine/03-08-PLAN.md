<task type="tracer">
  <name>Task 1: Recovery of a clean multi-segment log into locations and preamble state</name>
  <files>src/wal/recovery.rs</files>
  <read_first>src/wal/segment.rs (WalStart, SegmentSummary, PreambleState, Preamble, parse_segment_name, WalConfig); src/wal/record.rs (decode_record, Decoded, RecordType and the payload layouts for Entry, TruncateAfter, Purge in the interfaces block of plan 03-07 and 03-03); src/wal/io.rs (SegmentIo, FakeIo); 03-RESEARCH.md Pattern 1 Recovery paragraph</read_first>
  <action>
Create the recover function and RecoveredLog in src/wal/recovery.rs. Algorithm: list_segments; none returns an empty log with WalStart::fresh(). Require the sequence numbers to be consecutive from the lowest present (a gap is WalError::Corrupt). For each segment in ascending order read its whole image with SegmentIo::read_at (one segment at a time, at most segment_size bytes), then walk records with decode_record: the first record must be a Preamble whose segment_seq equals the file name's sequence and whose format_version is supported (decode_preamble checks it), and it seeds the running PreambleState for the first segment; later segments' preambles replace the state wholesale (they re-emit the state at roll time) and subsequent records update it in order. Entry records add an EntryLocation (index from the payload's first 8 bytes, seq, record start offset, total record length) and must have index equal to the previous logical last index plus one unless the logical log is empty, otherwise Corrupt. Vote and Committed replace the corresponding blob. Purge (payload upto u64 LE then blob) sets purged and drops locations with index at or below upto. TruncateAfter drops locations above keep_through (None drops all). End or Invalid stops the segment. At the end build SegmentSummary per segment from the surviving locations (first and last index, None for segments with no surviving entries), set WalStart.active_seq to the highest segment and tail_offset to the offset where scanning stopped in it. Define RecoveryStats and RecoveredLog::stats() as in the interfaces block (the torn-bytes counter is filled in Task 2; Task 1 leaves it 0).

Provide `test_support` under #[cfg(test)] pub(crate): a small builder that creates segments on any SegmentIo and appends records using encode_record and Preamble encoding, so tests can state a log declaratively (segment with entries 1..3 and a vote, and so on).

Test recovers_clean_log_into_locations_and_state: two segments built with the builder (entries 1-3 in segment 1 with a Vote, entries 4-5 plus a Committed in segment 2 whose preamble re-emits the vote); recover on FakeIo returns five contiguous locations with correct seq and offsets (verify by decoding each location back through io.read_at), start.active_seq 2, tail_offset equal to the end of the last record, state.vote and state.committed equal to the written blobs, torn_bytes_discarded 0.
  </action>

  </verify>

    - cache_never_evicts_unflushed: with a tiny budget, entries above the flushed watermark stay cached even when the budget is exceeded; after set_flushed they become evictable oldest-first until bytes is within budget
    - budget_evicts_oldest_flushed
    - truncate_drops_suffix_from_index_and_cache and purge_drops_prefix_from_index_and_cache
    - log_index_push_requires_contiguous_indices (non-contiguous push is a programmer error caught by a debug assertion and a returned WalError in release)
    - shared_observer_applies_callbacks_in_order (written, truncate, written again, purge, flushed)
    - miss_reads_from_disk_via_location: after eviction read_entry fetches the record through a SegmentRead handle on a FakeIo built with the test builder and decodes it with the supplied closure
  </behavior>
  <action>
Implement the types in the interfaces block. LogIndex stores locations contiguously in a VecDeque keyed by index minus first index so lookup is O(1) and memory is about 20 bytes per entry. EntryCache keeps a VecDeque of (index, entry, size) in ascending index order plus a running byte total and a flushed watermark; insert appends; set_flushed records the watermark and evicts from the front while bytes exceed budget and the front index is at or below the watermark (an entry above the watermark is never evicted, so the offset index always knows where an evicted entry lives); get is a binary search or offset arithmetic over the deque. SharedObserver implements WalObserver by taking the write lock briefly and applying on_entries_written to LogIndex, on_truncate and on_purge to both LogIndex and EntryCache (idempotent when the store already truncated the cache), and on_flushed to set_flushed. read_entry takes the read lock to check the cache, falls back to the LogIndex location and a single SegmentRead::read_at for the record length, decodes the record, checks type and index, and calls the supplied decode closure on the body.
  </action>
